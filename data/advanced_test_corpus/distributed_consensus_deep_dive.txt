Distributed Consensus Deep Dive: FLP, Paxos, Leases, and Linearizability

The FLP impossibility result shows that in a fully asynchronous system with even one crash failure, no deterministic consensus algorithm can guarantee termination in every possible execution while preserving agreement and validity. Practical systems add timing assumptions, failure detectors, randomized techniques, or partial synchrony to make progress possible.

Paxos chooses a value through numbered proposals and promises. Multi-Paxos optimises repeated decisions by establishing a stable leader that can reuse a ballot for many log entries. A leader lease is a time-bounded assumption that the leader remains authoritative; clock drift, pauses, and network delay must be accounted for before using leases to serve reads safely.

Split-brain occurs when multiple nodes act as leaders for the same logical service. Epoch numbers, fencing tokens, quorum rules, and lease discipline help reject operations from stale leaders. A fencing token must be checked by the protected resource, not merely generated by the coordinator.

Linearizability requires each operation to appear to take effect at one instant between invocation and response, while respecting real-time ordering of non-overlapping operations. Consensus can help implement linearizable replicated state machines, but the application must also handle retries, duplicate requests, snapshots, and durable log recovery.
